# 基于人体姿态估计与多类型分类模型的视频跌倒检测

本课程项目计划用普通摄像头视频完成跌倒（`fall`）与日常活动（`adl`）二分类：先用 MediaPipe BlazePose 提取 33 个人体关键点，再比较随机森林（RF）、LSTM、时空图卷积网络（ST-GCN）和轻量 Transformer Encoder 对连续姿态的识别能力。研究目标与实验设计见上级目录的[《实验方案》](../实验方案.md)。

实验重点回答：仅用骨架关键点能否识别跌倒；显式时序建模及骨架拓扑建模能否优于 RF；增加速度、躯干倾角等运动特征是否有效；以及不同模型在跌倒召回率、准确率、模型复杂度和实时性之间如何取舍。最终结论将基于统一划分的分组交叉验证和误差分析，而不是预设最佳模型。

**当前进度：**仓库已实现 URFD 图像帧的姿态提取、坐标归一化，以及基于 `x/y` 坐标的 RF 窗口级实验。LSTM、ST-GCN、Transformer、运动特征、视频级主评价和实时性测试仍在计划中。下文将已实现流程与后续工作分开说明。

## 环境准备

- Python 3.11（`pyproject.toml` 要求 Python ≥3.11，仓库的 `.python-version` 为 3.11）
- 推荐使用 uv 管理环境；依赖定义见 `pyproject.toml`

在项目根目录执行：

```bash
uv sync
```

下文命令均从项目根目录运行。若不使用 uv，也可以用 Python 3.11 创建虚拟环境并安装 `pyproject.toml` 中的依赖。

## 数据准备

当前代码针对 URFD 数据集的 `cam0-rgb` 图像帧，按 **30 FPS** 处理。将解压后的 PNG 帧放到以下目录；每段视频的帧可以直接位于视频目录，也可以再嵌套一层同名目录：

```text
data/raw/
├── adl/
│   └── adl-01-cam0-rgb/
│       └── adl-01-cam0-rgb-001.png
└── fall/
    └── fall-01-cam0-rgb/
        └── fall-01-cam0-rgb-001.png
```

帧文件名末尾须带数字帧号，例如 `-001.png`。类别由 `adl`、`fall` 两级目录名决定。原始数据与生成的关键点文件未纳入仓库。

`data/download_urfd_adl.sh` 和 `data/download_urfd_falls.sh` 是下载脚本草稿
（完成之后改了下文件目录结构，脚本可能路径有点问题需要自己修正）

## 运行实验

### 1. 提取姿态关键点

```bash
uv run python src/blazepose.py
```

脚本对每张图片独立运行 BlazePose Heavy，输出 `data/keypoints/{adl,fall}/<video_id>.npz`，并在 `data/pose/visualization/` 保存少量抽样图片。每个 NPZ 包含：

| 字段 | 含义 |
| --- | --- |
| `keypoints` | `[帧数, 33, 4]`；最后一维为 `x, y, z, visibility`，未检测到人体的帧为 NaN |
| `valid_mask` | 每帧是否检测到人体 |
| `frame_indices`, `timestamps`, `fps` | 原始帧号、秒级时间戳和帧率 |
| `label`, `video_id` | 视频类别与编号 |

### 2. 归一化坐标

```bash
uv run python src/normalize_keypoints.py
```

脚本读取 `data/keypoints/`，将髋部中心作为坐标原点、肩宽作为优先尺度，输出同结构文件至 `data/keypoints_normalized/`。无法可靠归一化的帧会标记为无效。

### 3. 训练并评估随机森林

```bash
uv run python src/experiment_rf.py
```

脚本当前默认读取 **归一化** 关键点，输出到 `results/rf_sliding_raw_1s_normalized/`。若要运行原始坐标实验，先在 `src/experiment_rf.py` 顶部将 `DATA_ROOT` 改为 `Path("data/keypoints")`，并将 `EXPERIMENT_NAME` 改为新的结果目录名，然后重新运行。实验参数目前通过修改脚本顶部常量配置，没有命令行参数。

每个窗口包含 30 帧（1 秒），步长为 1 帧；使用 33 个关键点的 `x/y` 坐标，展开后为 1980 维。低可见度或缺失坐标在窗口内按时间插值。分类标签为 `adl=0`、`fall=1`。评估采用按视频分组的分层交叉验证，同一视频的窗口不会同时进入训练集和测试集。交叉验证完成后，脚本再用全部窗口训练并保存最终模型。

结果目录包含 `config.json`、`metrics.txt`、`fold_metrics.csv`、`confusion_matrix.csv`、`window_predictions.csv`、`feature_importance.csv` 和最终模型 `.joblib`。`metrics.txt` 中的总体指标来自各折测试窗口的汇总预测；它们是**窗口级**指标，不是独立视频或实时场景的检测指标。

## 已有实验结果

### MLP 实验程序

新增 `src/experiment_mlp.py`，可作为将连续 30 帧关键点展平后分类的神经网络基线。从项目根目录运行：

```bash
uv run python src/experiment_mlp.py --data-root data/keypoints_normalized
```

原始坐标实验可把数据目录改为 `data/keypoints`。默认使用全部 33 个关节的 `x/y`、30 帧窗口、1 帧步长、缺失坐标时间插值和两层 MLP（256、64 个隐藏单元）。五折按视频分组，训练折内再按视频划分验证集用于早停；标准化参数仅由内部训练视频计算。输出分别保存在 `results/mlp_normalized/` 或 `results/mlp/`，包含窗口级和视频级折外预测、指标、训练曲线及各折模型。视频级结果按同一视频各窗口的跌倒概率平均后计算。

目前仓库没有提交关键点 NPZ 数据，因此这里没有 MLP 实测指标。

仓库已保存两组随机森林实验结果，均基于 70 段视频、8993 个窗口和 5 折按视频分组评估：

| 输入 | 准确率 | 跌倒精确率 | 跌倒召回率 | 跌倒 F1 | ROC-AUC |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始坐标（`rf_sliding_raw_1s`） | 0.9158 | 0.8327 | 0.8014 | 0.8168 | 0.9507 |
| 归一化坐标（`rf_sliding_raw_1s_normalized`） | 0.8589 | 0.7419 | 0.6090 | 0.6689 | 0.9093 |

这些数值记录在各结果目录的 `metrics.txt` 中，属于**初步 RF 基线**，不能作为实验方案中四模型主对比的最终结果。当前实现将整段视频的 `fall` 或 `adl` 标签赋给该视频的所有窗口，因此跌倒视频中实际尚未发生跌倒的片段也会被标为 `fall`；解读窗口级指标时应考虑这一点。

当前实现与实验方案的主要差异如下：

| 环节 | 当前项目 | 实验方案目标 |
| --- | --- | --- |
| 姿态提取 | 每帧独立检测，`static_image_mode=True`、`model_complexity=2` | 跟踪模式、`model_complexity=1` |
| RF 输入与切窗 | `x/y`、30 帧窗口、1 帧步长 | 四模型统一使用 `x/y/visibility`、30 帧窗口、15 帧步长 |
| RF 训练 | 固定 500 棵树，直接进行五折评估 | 每折内部验证集选参数，外层五折统一评估 |
| 标签与主指标 | 整段视频标签赋给所有窗口，报告窗口级指标 | 核对跌倒区间，以视频级折外指标为主 |

## 后续实验计划

以下内容依据《实验方案》，**尚未由当前仓库代码实现**。开展四模型主对比前，需要先统一数据、标签和评价规则；现有 RF 结果不能直接与将来按新规则运行的模型结果横向比较。

1. **建立可信的数据划分与标签。**整理 30 段跌倒和 40 段非跌倒视频的元数据，检查关键点提取质量，并核对跌倒发生区间。优先按人物分组；若人物信息或类别分布不支持五折，则按原始视频分组。保存统一的五折清单，每折再从训练候选视频中划内部验证集。仅在训练部分拟合需要学习的预处理参数、选择模型和阈值，外层折只用于最终评价。
2. **统一输入与窗口规则。**主对比使用归一化后的 `x、y、visibility`，默认 30 帧窗口、15 帧步长。按实验方案处理缺失关键点和低质量窗口；若只有视频级标签，应先补充跌倒发生区间或截取明确包含跌倒动作的片段，避免把跌倒前的正常活动窗口标为跌倒。当前 RF 脚本使用 `x/y`、1 帧步长和整段视频标签，后续需调整并重新运行。
3. **完成四模型主对比。**在相同五折、窗口来源和标签下，运行 RF、单层 LSTM、轻量 ST-GCN 和轻量 Transformer。RF 展平窗口；LSTM 与 Transformer 保留时间维；ST-GCN 同时保留时间维和骨架连接。按内部验证集选择超参数和最佳轮次，并记录多个随机种子的结果。
4. **补齐评价体系。**以视频为单位汇总窗口跌倒概率，用预先固定的规则得到视频级预测；报告五折 Accuracy、跌倒 Precision、Recall、F1 的均值与标准差，以及总体混淆矩阵、ROC-AUC 和 PR-AUC。窗口级指标作为补充。重点检查漏检和误报，不能只看准确率。
5. **做消融、敏感性和实时性实验。**在统一评价流程下比较坐标、坐标加可见度、坐标加速度及完整运动特征；比较 15、30、60 帧窗口；在同一设备上分别测姿态提取耗时、分类器耗时、端到端 FPS、模型大小和资源消耗。
6. **分析错误并扩展验证。**查看典型漏检、误报视频及其概率时间曲线，分析遮挡、相似日常动作和关键点失败等原因。有余力时再测试遮挡鲁棒性、跨视角或场景泛化，以及加入 `z` 坐标的效果。

目前 `pyproject.toml` 只包含已实现流程所需的依赖；开始深度模型实验时，还需按实际实现补充相应框架依赖与训练脚本。实验方案中的网络结构和训练参数是后续实现目标，不代表仓库已经提供这些功能。
